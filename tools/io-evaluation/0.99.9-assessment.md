# GeneTrackR 0.99.9 standard backend assessment

Run from the source checkout with the matching GeneTrackR installed alongside
Rsamtools, VariantAnnotation, txdbmaker and GenomicFeatures.

```sh
Rscript tools/assess_standard_backends.R temp/standard-backends-0.99.9
```

## TxDb hierarchy mapping

The eight GFF3 records contain two genes, three transcripts, two exons and one
CDS. The comparison keys are transcript ID, chromosome, 1-based closed start
and end, and strand, grouped by feature type. The synthetic annotation has
no genome build designation. [Fixture](fixtures/annotation.gff3) · [All input record counts](0.99.9-gff3-records.csv)

| Feature | Input rows | Declared memberships | Primary memberships | TxDb memberships matched | GFF3 only | TxDb only |
|---|---:|---:|---:|---:|---:|---:|
| Transcript | 3 | 3 | 3 | 3 | 0 | 0 |
| Exon | 2 | 3 | 2 | 3 | 0 | 0 |
| CDS | 1 | 1 | 1 | 1 | 0 | 0 |

The raw TxDb keys use the display names `Tx1`, `Tx2` and `Tx3`, so none
match the raw GFF3 IDs directly. The fixture declares a unique `Name` for
each `ID`. Matching through those declarations resolves all seven keys.
The shared exon at `chr1:1-5` belongs to both `t1` and `t2` in the GFF3 and
TxDb. GeneTrackR retains both parents in `parent_ids` and uses `t1` in its
primary assignment. [Counts](0.99.9-txdb-counts.csv) · [Rows](0.99.9-txdb-rows.csv) · [Name mapping](0.99.9-txdb-name-map.csv)

## Indexed VCF comparison

The synthetic index contains 50,000 sites and eight samples. Both readers
return 51 Tabix overlaps for `chr1:100001-100500`. One deletion starts before
the query and spans its left boundary. Applying the same 1-based inclusive
POS filter yields 50 sites per reader, with all 50 keys, REF/ALT, depth, sample
order and phased GT fields matching the generated reference. The 49,950
input sites outside that POS interval are excluded by the same criterion.

| Reader | Matched / expected | Namespace load (s) | Namespaces loaded | Median read (s) | Peak working set (MiB) |
|---|---:|---:|---:|---:|---:|
| GeneTrackR 0.99.9 | 50 / 50 | 1.53 | 20 | 0.02 | 374.6 |
| VariantAnnotation 1.59.4 | 50 / 50 | 6.40 | 58 | 0.08 | 865.9 |

Each reader ran in a separate R process. Timing is the median of three reads
after namespace loading. The Windows `PeakWorkingSet64` measurement includes
startup, dependency loading, query and garbage collection up to the peak
measurement. It excludes comparison and report writing. OS caching and the
synthetic query size limit extrapolation to real workloads. The assessment
was executed on Windows with R 4.6.1. Linux/macOS and large real datasets
remain to be measured. [Indexed results](0.99.9-indexed-vcf.csv) · [Versions and fixture hashes](0.99.9-backends-metadata.dcf)

## Decisions for further evaluation

| Area | Evidence needed for a migration decision |
|---|---|
| Multi-parent models | Build an opt-in parent-edge projection with stable source rows and ID keys. Check counts and totals for shared exons and CDS across transcripts, and preserve the primary model for existing calls. |
| BED12 to gene models | Prove block and thick-span round trips when gene and transcript identifiers are supplied explicitly. Keep flat records when the input cannot identify a unique hierarchy. |
| Alternate VCF backend | Test full file and indexed queries on large real datasets across the three platforms. Verify field types, missingness, sample order, written precision, dependency footprint and lazy/RDS compatibility before changing defaults. |

The typed VCF boundary uses VariantAnnotation for representation and writing.
The adapter retains exact typed data in memory. The standard file writer can
round floating-point FORMAT values, update `fileDate` and pad arrays.
See [VariantAnnotation documentation](https://bioconductor.org/packages/devel/bioc/vignettes/VariantAnnotation/inst/doc/VariantAnnotation.html)
and [txdbmaker documentation](https://bioconductor.org/packages/txdbmaker/).
